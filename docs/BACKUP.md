# גיבוי Supabase החי לפני הפעלת מערכת הניהול

**הגיבוי קורא נתונים בלבד:** שום דבר בפרויקט לא משתנה. לא צריך Docker.

## איזה גיבוי מתאים לתוכנית שלך
- **Free:** ל־Supabase אין גיבוי יומי בתוכנית הזו. Supabase ממליצה לייצא בעצמך, ולכן **הסקריפט כאן הוא הגיבוי שלך.**
- **Pro ומעלה:** ב־Database ← Backups מופיעים גיבויים יומיים (7 ימים ב־Pro), ואפשר לשחזר מהם מה־Dashboard. **מומלץ להריץ גם את הסקריפט**, כדי שיהיה עותק אצלך.

**איך יודעים איזו תוכנית יש לך:** Dashboard ← Organization ← Billing. או: אם ב־Database ← Backups אין רשימת גיבויים, זו תוכנית Free.

## גיבוי (כ־5 דקות, פעם אחת לפני ההפעלה)
1. **כלי PostgreSQL**, חינמי. ב־Terminal:
   `brew install libpq`
2. **מחרוזת החיבור:** ב־Supabase לוחצים **Connect**, למעלה בפרויקט, בוחרים **Session pooler** ומעתיקים את ה־URI.
   - הוא נראה כך: `postgresql://postgres.<ref>:[YOUR-PASSWORD]@aws-0-<region>.pooler.supabase.com:5432/postgres`.
   - משאירים בו את `[YOUR-PASSWORD]` כמו שהוא.
3. **הרצה:** בתיקייה שבה נמצא `backup_sofitgo.sh`:
   `bash backup_sofitgo.sh`
   - מדביקים את ה־URI.
   - מקלידים את **סיסמת מסד הנתונים**. היא לא מוצגת, לא נשמרת ולא נכתבת לשום קובץ.
4. **התוצאה:** תיקייה `~/Documents/SoFitGo-Backup/<תאריך>` ובה שלושה קבצים:
   - `sofitgo-public.dump`: כל הטבלאות של האפליקציה, מבנה ונתונים;
   - `sofitgo-auth-users.dump`: חשבונות המשתמשים;
   - `SHA256SUMS.txt`.
5. **הבדיקה הסופית** מודפסת בסוף הריצה: טבלה עם מספר השורות בכל טבלה, בשרת ובגיבוי.
   - **ממשיכים להפעלה רק אם מופיע `BACKUP OK`.**
   - אם מופיע `MISMATCH`, לא ממשיכים, ושולחים לי את הטבלה בלי הסיסמה.

**אם הסיסמה לא ידועה לך:** Project Settings ← Database ← **Reset database password**.
- **שינוי סיסמה הוא שינוי בייצור.** הוא לא משפיע על האפליקציה, כי היא משתמשת רק במפתח הציבורי, אבל הוא ינתק כל כלי חיצוני שמתחבר עם הסיסמה הישנה, אם יש כזה.
- את הסיסמה החדשה שומרים במנהל סיסמאות.

**אבטחה:** הקבצים מכילים מיילים ונתונים אישיים של משתמשים.
- שומרים אותם בכונן מוצפן. ב־Mac, FileVault מצפין את כל הדיסק.
- **לא שולחים אותם במייל או בצ'אט.**

## שחזור
**בתרחיש הרגיל לא צריך שחזור נתונים:** ההפעלה לא מוחקת ולא משנה שום שורה קיימת. זה נבדק על מסד שמשחזר את הסכמה החיה.
- **ביטול מערכת הניהול:** `undo_admin.sql` בלבד. הוא מחזיר בדיוק את המבנה הקודם, וחשבונות ונתוני משתמשים נשארים.

**שחזור נתונים מהגיבוי** נדרש רק במקרה חירום, אם נתונים אבדו מסיבה אחרת. זו פעולה בייצור, ומבצעים אותה יחד איתי, טבלה אחר טבלה:
- **Pro:** Database ← Backups ← **Restore** לגיבוי הרצוי. זה מחזיר את כל הפרויקט לאותו יום.
- **Free, או שחזור חלקי:** מהקבצים שגיבית, עם `pg_restore`.
  - אני אכין לך את הפקודה המדויקת לטבלה שצריך, אחרי שנבדוק מה בדיוק חסר.
  - **לא מריצים `pg_restore` על הפרויקט החי בלי זה.** שחזור על נתונים קיימים עלול ליצור כפילויות.

**מה נבדק אצלי:** שחזור מלא של אותם שני קבצים לתוך מסד ריק במחשב, באותן פקודות, החזיר את כל השורות. הסקריפט עצמו נבדק מול מסד מקומי, וכל הטבלאות התאימו.
