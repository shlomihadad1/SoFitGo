# התקנה, עדכון וחזרה לגרסה קודמת — SoFitGo Beta

**שלוש צורות הפצה. חשוב לדעת מה כל אחת:**

| קובץ | מה זה | למי |
|---|---|---|
| `sofitgo-devtest-<build>-<commit>.zip` | **אתר Web מוכן** (PWA בנוי, לא קוד מקור). כולל שרת בדיקה מקומי (`serve_beta.py`). הכול נשמר במכשיר; אין חיבור לשרת | iPhone ו־Android, דרך מחשב ברשת הביתית |
| `sofitgo-beta-<build>-<commit>.apk` | **חבילת התקנה ל־Android** (אפליקציית WebView שמכילה את אותו build). חתומה במפתח בדיקה; לא מחנות Google Play | Android 7.0 ומעלה |
| `sofitgo-beta-<build>-<commit>.zip` | אתר Web מוכן **עם** הגדרת השרת (חשבונות) — מיועד לפריסה **רק אחרי אישורך** | לא לשימוש עכשיו |

**אין חבילת התקנה ל־iOS.** כדי ליצור אחת צריך Mac עם Xcode, חשבון Apple Developer בתשלום (99$ לשנה) ו־TestFlight. לכן ב־iPhone פותחים את האפליקציה כאתר.

## 1. Android — התקנת ה־APK (הכי פשוט, בלי מחשב)
1. מעבירים את קובץ ה־APK לטלפון: במייל, ב־Google Drive או בכבל.
2. פותחים אותו. Android מבקש לאשר "התקנה ממקור לא ידוע" לאפליקציה שממנה פתחתם (Files, Chrome או Gmail). מאשרים רק עבור הקובץ הזה.
3. Play Protect עשוי להזהיר שהאפליקציה לא מוכרת. בוחרים "התקנה בכל זאת".
4. פותחים את **SoFitGo Beta**. הקבצים נמצאים בתוך האפליקציה, כך שמצב אימון ושאר המסכים עובדים גם בלי אינטרנט. גופנים נטענים מהרשת, ובלי חיבור מוצגים גופני המערכת. לא נבדק על טלפון אמיתי.
5. **מה שונה מהאתר:**
   - קבצי CSV והגיבוי נשמרים בתיקיית ההורדות;
   - המסך נשאר דלוק בזמן אימון;
   - מיקום מתבקש רק ב"אוכל בקרבתי".

## 2. iPhone (וגם Android) — אתר דרך המחשב בבית
**למה צריך מחשב:** iPhone לא מריץ אתר מתוך קובץ ZIP. קובץ HTML שנפתח מאפליקציית "קבצים" לא מריץ את האפליקציה. צריך משהו שיגיש את הקבצים, והמחשב הוא זה. זה נשאר בתוך הרשת הביתית, בלי פריסה ובלי עלות.

### צעד אחר צעד
1. **במחשב:** מורידים את `sofitgo-devtest-….zip` ופורקים אותו. נוצרת תיקייה `sofitgo`.
2. **פותחים מסוף בתוך התיקייה:**
   - **Mac:** Finder ← קליק ימני על התיקייה `sofitgo` ← "שירותים" ← "מסוף חדש בתיקייה". אם האפשרות לא מופיעה: פותחים Terminal, מקלידים `cd ` (עם רווח) וגוררים את התיקייה לחלון.
   - **Windows:** פותחים את התיקייה, כותבים `cmd` בשורת הכתובת ולוחצים Enter. אם Python לא מותקן, מתקינים אותו מ־python.org ומסמנים "Add to PATH".
3. **מריצים:** `python3 serve_beta.py` (ב־Windows: `py serve_beta.py`).
4. **השרת מדפיס כתובת**, למשל `http://192.168.1.23:8080/`. ב־Mac עשויה להופיע שאלה אם לאפשר חיבורים נכנסים ל־Python: עונים "אפשר". ב־Windows: מאשרים "רשתות פרטיות" בלבד.
5. **ב־iPhone**, מחובר לאותה רשת Wi‑Fi: פותחים **Safari** ומקלידים את הכתובת **בדיוק**, כולל `http://` ומספר הפורט.
6. **אופציונלי:** שיתוף ← "הוספה למסך הבית" יוצר אייקון. בדרך הזו הוא נפתח רק כשהמחשב והשרת פועלים.
7. **בסיום:** Ctrl+C במסוף. כדי שהנתונים יישמרו לפעם הבאה, מריצים שוב באותו מחשב ובאותו פורט. הכתובת עשויה להשתנות אם הנתב נותן למחשב IP אחר. במקרה כזה הנתונים בכתובת הישנה לא עוברים לבד, ומעבירים אותם עם גיבוי JSON.

### מה אפשר לבדוק בדרך הזו (HTTP), ומה לא
| עובד | לא עובד בדרך הזו |
|---|---|
| כל המסכים; מצב אימון; שמירה אחרי כל פעולה; רענון; סגירה כפויה; נעילת מסך וחזרה מרקע; לחיצות כפולות; תזונה; ייצוא CSV | פתיחה בלי אינטרנט אחרי רענון (Service Worker); השארת מסך דלוק (Wake Lock); התקנה מלאה כאפליקציה |

**לבדיקה מלאה גם באייפון** צריך HTTPS עם תעודה שהאייפון סומך עליה (mkcert, חינמי). ההוראות ב־`docs/DEVICE_TEST_PLAN.md` §1, דרך ג.

### חלופות בלי מחשב (כל אחת דורשת את אישורך)
- **(א) דף פרטי ב־claude.ai:** אותו build כקובץ יחיד, פתוח רק לך. לא נוגע ב־Netlify או ב־Production, אבל הוא אחסון באינטרנט. הנתונים נשמרים רק בדף הזה, ואין מצב לא מקוון.
- **(ב) Netlify Draft Deploy:** כתובת זמנית שאינה Production. זו בכל זאת פריסה.

## 3. עדכון לגרסה חדשה
**כלל:** הנתונים שמורים לפי **כתובת** (origin). עדכון באותה כתובת שומר אותם. מעבר לכתובת אחרת לא מעביר אותם. במקרה כזה: גיבוי JSON בכתובת הישנה, ושחזור בחדשה (מרכז פרטיות ← גיבוי מלא; הגדרות ← "שחזור מגיבוי").

| צורה | איך מעדכנים | הנתונים |
|---|---|---|
| אתר מקומי (devtest) | מחליפים את התיקייה בגרסה החדשה, ומריצים את השרת באותו פורט ובאותו מחשב. בטלפון: סוגרים ופותחים | נשמרים, כי זו אותה כתובת |
| APK | מתקינים את ה־APK החדש מעל הישן. הוא חתום באותו מפתח, ומספר הגרסה עולה | נשמרים |
| אתר חי (בעתיד) | פריסה של `dist/pwa` באישורך. המשתמשים מקבלים את הגרסה בפתיחה הבאה עם חיבור, כי הדף נטען מהרשת קודם | נשמרים |

**מפתח החתימה של ה־APK:** שמור **מחוץ ל־repo**. יש לשמור אותו: Android מסרב לעדכון שחתום במפתח אחר. במקרה כזה צריך להסיר את האפליקציה, וזה מוחק את הנתונים שלה.

## 4. חזרה לגרסה קודמת
- **אתר מקומי:** מריצים את השרת על התיקייה של הגרסה הקודמת.
- **APK:** Android לא מתקין גרסה ישנה מעל חדשה. לכן: גיבוי JSON (מרכז פרטיות) ← הסרה ← התקנת הגרסה הקודמת ← שחזור.
- **אתר חי:** פריסה מחדש של ה־ZIP של הגרסה הקודמת. Netlify שומר גם היסטוריית פריסות, ואפשר לשחזר ממנה (Deploys ← Publish deploy).

## 5. בנייה חוזרת (למפתחים)
```
git checkout <commit>
NODE_PATH=<node_modules> node tools/build.js                 # dist/pwa, Build ID ב־sw.js
ANDROID_HOME=<sdk> SOFITGO_KEYSTORE=<path> SOFITGO_KEYSTORE_PASS=<…> sh native/android-webview/build_apk.sh
```
**דרישות ל־APK:** JDK 17, ‏Gradle 8.13 ומעלה, ו־Android SDK 35.

הבנייה של אותו commit נותנת את אותו Build ID. מזהה ה־commit מופיע בשם הקבצים ובדוח הראיות (`docs/release/`).
