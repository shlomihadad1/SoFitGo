# מפתח החתימה של אפליקציית Android לבדיקה

## למה זה חשוב
Android מתקין עדכון רק אם הוא חתום **באותו מפתח** כמו הגרסה שכבר מותקנת.

**אם המפתח אובד:**
- אי אפשר לעדכן את האפליקציה.
- צריך להסיר אותה, וזה מוחק את הנתונים שבתוכה.
- לפני הסרה כזו: גיבוי JSON במרכז הפרטיות, ושחזור אחרי ההתקנה.

## איפה המפתח נמצא עכשיו
- **מיקום:** בתיקייה זמנית של סביבת העבודה, `…/scratchpad/android-key/`, עם הרשאות 600.
- **לא ב־repo:** לא ב־ZIP, לא במסמכים ולא בצ'אט.
- **התיקייה הזו לא קבועה.** היא נמחקת כשהסביבה מתאפסת. לכן **צריך גיבוי מחוץ לה**. זו פעולה שלך (ראו למטה).

## גיבוי בטוח (פעולה שלך)
1. **מקשרים את השיחה למחשב:** פותחים אותה באפליקציית Claude למחשב ובוחרים "Link to this computer". אחר כך מבקשים: "שמור את מפתח ה־Android בתיקייה X".
   - הקובץ `beta.jks` ייכתב לתיקייה שבחרת.
   - **הסיסמה לא תופיע בצ'אט.** היא תיכתב לקובץ נפרד באותה תיקייה, ותעביר אותה מיד למנהל הסיסמאות שלך.
2. **שומרים בשני מקומות נפרדים:**
   - הקובץ `beta.jks`: כונן מוצפן או גיבוי מוצפן.
   - הסיסמה: מנהל סיסמאות.
   - **לא באותו מקום, ולא בתיבת מייל.**
3. **אחרי ששמרת:** מוחקים את קובץ הסיסמה מהתיקייה.

## איך מוודאים שהגיבוי ניתן לשחזור
במחשב עם JDK:
```
keytool -list -v -keystore beta.jks -alias sofitgo-beta
```
מקלידים את הסיסמה כשמתבקשים. הפקודה צריכה להציג את טביעת האצבע SHA-256 שבטבלה למעלה.

ובדיקה מול APK חתום:
```
apksigner verify --print-certs sofitgo-beta-<build>-<commit>.apk
```
השורה `Signer #1 certificate SHA-256 digest` צריכה להתאים לאותה טביעת אצבע. אפשר להשוות בלי נקודתיים, באותיות קטנות.

**המקור בסביבה לא יימחק לפני שאישרת שהגיבוי נבדק.**

## אם המפתח כבר אבד
1. יוצרים מפתח חדש: `keytool -genkeypair -alias sofitgo-beta -keyalg RSA -keysize 3072 -validity 10000 -keystore beta.jks`.
2. בונים מחדש עם `build_apk.sh`.
3. בכל טלפון: גיבוי JSON ← הסרת האפליקציה ← התקנה ← שחזור.

## לפני חנות Google Play
ב־Play משתמשים ב־Play App Signing: Google מחזיקה את מפתח ההפצה, ואתה מחזיק מפתח העלאה. זה דורש חשבון מפתח בתשלום חד־פעמי (25$), ולכן מחכה לאישורך.
